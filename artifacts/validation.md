# SqueekBurrow validation

Worker observations, **6 November 2026**. These results are reproducible checks, not independent certification.

## Scope and completion

Implemented and checked: the actual production static export, local recorded-round practice, all four assignments, deterministic survival rules, shared Node/SQLite service, official API and contract integration, season results, and source/build documentation.

**The local implementation and static deliverable are complete. Public shared-live launch is incomplete.** The repository and static website are ready for IMD publication under the requested label `squeekburrow`. A public shared backend has not been hosted; the static export explicitly ships with `serviceUrl: null`. No public repository/demo URLs were assigned during this run. The backend was exercised locally against the real official service and chain. Its operational instructions are in the README. A static demo cannot provide authoritative shared multiplayer without that service, and does not claim to do so.

Ordinary implementation choices: a 24-round season; one Bramblewood colony per service; anonymous browser sessions; 15-second assignment cutoff; no financial or wallet features; one light theme; English interface. Practice uses actual recorded rounds with two labeled computer helpers, rather than inventing current rounds.

## Remaining limitations

1. **Public backend and publication:** shared live multiplayer is implemented and tested locally, but no public backend has been provisioned. IMD repository/static-site publication and actual public URLs are outside the worker's demonstrated result. The static site is honestly labeled practice until a service is configured.
2. **Browser runtime:** the supplied full Chromium/browser connector could not launch because its process-singleton socket operation was denied. Working Chromium headless shell and direct Playwright were used for all rendered evidence. The sandbox also canceled a minimal standalone file download, as well as the game's download. The actual recap event and payload pass; a native filesystem save does not.
3. **External browser network:** direct browser requests to the official API were blocked in the automation environment. The static UI visibly reported wheel-feed unavailability. Node successfully fetched the real API and RPC, and the browser used the real backend's verified data in live mode. Browser-to-official-API connectivity on the future public demo remains unverified.
4. **Live duration:** checks committed a real current-round assignment and decoded confirmed historical rounds. They did not wait ten minutes for that particular round's confirmation or run a real four-hour season. Settlement, consecutive recovery, duplicate protection, win and loss are tested deterministically using actual historical records.
5. **Operational trust:** this is a centrally operated cooperative game, not a trustless multiplayer protocol. The service, official API, RPC and host clock are trusted. Anonymous sessions and per-IP rate limits do not prevent multiple identities. Upstream deployment changes intentionally stop play. Browser storage loss has no account recovery.
6. **Manual accessibility/device coverage:** no physical phone, screen reader, WebKit, Firefox, native zoom, RTL or translated-language certification is claimed. Automated no-violation reports are limited to the checked states.
